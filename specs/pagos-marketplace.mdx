## Contexto

El Marketplace tiene muchas integraciones de pago: Stripe, Mercado Pago, De Una, Payphone, Wompi, PayPal, Kushki, Conekta, Datafast, Nuvei y Jelou Payments. En los flujos funcionan bien.

El problema está en el AI Agent. Solo acepta integraciones MCP, y la única de pagos que lo es hoy es Stripe. Si buscas "mercado pago" en **Agregar tool**, no aparece nada.

## Objetivo

Reutilizar las integraciones de pago que ya existen. Al instalar una, la plataforma crea por detrás un MCP para esa integración y el AI Agent lo ve igual que a Stripe. Ese MCP expone solo 2 tools: **Generar enlace de pago** y **Obtener estado del pedido**. Las credenciales, los datos técnicos y la información sensible se resuelven por detrás, nunca en la tool.

## Qué hace falta

### Instalación

- [ ] **1.** La instalación de una integración de pagos no cambia: mismo flujo y mismas credenciales de hoy, sin pasos ni inputs nuevos.
  Se mantiene el modal **Conectar** actual con sus dos opciones:
  - **Probar con Jelou**: prueba la integración sin crear una cuenta ni ingresar credenciales.
  - **Conectar mi cuenta**: usa las credenciales propias, en ambiente de prueba o producción.
- [ ] **2.** Al instalarla, se crea automáticamente un MCP para esa integración. Hay un MCP por integración instalada, incluida Stripe. Reutiliza la conexión al core de pagos del MCP **Jelou Payments** actual, con el proveedor fijado por la integración instalada. Las tools tienen un schema nuevo con solo los inputs del ítem **8**.
- [ ] **3.** Una company puede tener varias integraciones de pago instaladas a la vez, y un mismo agente puede usar varias.

### Vista en el Marketplace

- [ ] **4.** El detalle de la integración muestra la sección **Tools para AI Agent (MCP)** con sus 2 tools.
- [ ] **5.** Se eliminan las tools nativas **Pago WebView** y **Pago Confirmación Externa**: del detalle de cada integración y de **Agregar tool**. Los agentes que ya las usan siguen funcionando durante la ventana de deprecación. Ver [Migración](#migración).

### Vista en el agente

- [ ] **6.** En **Agregar tool**, las integraciones de pago instaladas aparecen bajo **Integraciones MCP**, como Stripe.
- [ ] **7.** Cada MCP de pagos expone exactamente 2 tools:
  - **Generar enlace de pago**: crea el pedido en el core de pagos de Jelou y devuelve el link (o código) de pago.
  - **Obtener estado del pedido**: indica si el pedido se pagó, sigue pendiente, falló o fue cancelado.

  Se muestran con el mismo patrón que Shopify y Jelou Shop hoy: el proveedor es una fila con el badge **ALL**, ⚙ y 🗑. Al abrir ⚙ se ve el switch **Integración completa** y, bajo **Herramientas específicas**, sus 2 tools con su propio switch.

### Inputs

- [ ] **8.** Las tools solo le piden al AI los datos que salen de la conversación. Propuesta:
  - **Generar enlace de pago**: `amount` y `concept`.
  - **Obtener estado del pedido**: `orderId`.

  El resto se resuelve por detrás o se configura una vez en **Pagos**. Ver [De dónde sale cada campo](#de-dónde-sale-cada-campo).

### Configuración en Pagos

- [ ] **9.** En **Pagos → Integraciones**, el botón **Configurar** de cada pasarela abre su configuración: moneda, país, IVA y expiración del link de pago. El MCP y los flujos toman esos valores de ahí. Si el comercio nunca abre **Configurar**, el MCP usa la moneda y el IVA del país de la pasarela y 30 minutos de expiración, así que cobra desde el primer día sin configurar nada.

### Después del pago

- [ ] **10.** **Generar enlace de pago** guarda el `executionId` del agente en el pedido. Cuando el core de pagos recibe el webhook del PSP, llama a `resume-or-create` del AI Agent: retoma la ejecución si sigue viva o crea una nueva con el resultado del pago. El agente retoma la conversación sin que el usuario tenga que escribir.

## De dónde sale cada campo

Hoy **Pago WebView** y el modal de **Jelou Payments** piden todo esto a quien arma el bot. Con el esquema nuevo cada campo tiene un solo origen.

### Lo pide el AI en la conversación

| Campo | Tool | Qué es |
| --- | --- | --- |
| `amount` | Generar enlace de pago | Monto total a cobrar |
| `concept` | Generar enlace de pago | Qué está pagando el usuario |
| `orderId` | Obtener estado del pedido | Id del pedido que devolvió el cobro |

### Lo resuelve el backend

Sale de la integración instalada y del contexto de la conversación. Nunca se muestra en la tool ni se pide al instalar el MCP.

| Campo | De dónde sale |
| --- | --- |
| `provider` | La integración instalada. Cada MCP pertenece a un solo proveedor. |
| Credenciales de la pasarela (API keys, llaves pública y privada, access token) | Con **Conectar mi cuenta**, las que se ingresaron al instalar la integración. Con **Probar con Jelou**, las credenciales sandbox de Jelou para esa pasarela. |
| Token del core de pagos | La company. |
| ID de la app de la company en el core de pagos | La company. |
| `environment` | El estado de la integración: **Desarrollo** o **Producción** (botón **Pasar a producción**). **Probar con Jelou** siempre es Desarrollo. |
| `botId`, `botNumber`, `botType` | El bot y el canal donde corre el agente. |
| `executionId` | La ejecución del agente que generó el link. Lo usa el core para retomar la conversación (**10**). |

### Se configura en Pagos → Integraciones

Son datos del comercio, no de cada cobro. Se definen una vez por pasarela con el botón **Configurar** (**9**) y el MCP los lee de ahí.

| Campo | Hoy | Propuesta | Default |
| --- | --- | --- | --- |
| Moneda | Se pide en cada tool (`currency`) | Configuración de la pasarela | La del país de la pasarela |
| IVA (%) | Se pide en cada tool (`iva`) | Configuración de la pasarela | El del país de la pasarela |
| País | Se pide al instalar Jelou Payments | Configuración de la pasarela | El de la pasarela |
| Expiración del link de pago | Se pide en cada tool (`expiration_time`) | Configuración de la pasarela | 30 minutos |

## Migración

**Pago WebView** y **Pago Confirmación Externa** se retiran con una ventana de deprecación, no de un día para otro. Son bots que cobran dinero en producción.

1. Desde el día 1 desaparecen de **Agregar tool** y del detalle de la integración. Nadie puede agregarlas a un agente nuevo.
2. Los agentes que ya las tienen siguen funcionando. En el builder se muestra un aviso en la tool con el MCP del proveedor como reemplazo.
3. Se levanta el inventario de bots que las usan. Con ese número se fija la fecha de corte y se contacta a cada company.
4. En la fecha de corte se retiran de los agentes que aún las tengan.

## Criterios de aceptación

- [ ] Dado que una company instala Wompi, cuando abre **Agregar tool** en un AI Agent, entonces Wompi aparece bajo **Integraciones MCP** sin configurar nada más.
- [ ] Dado que una company tiene Wompi y Mercado Pago instalados, cuando los agrega a un mismo agente, entonces cada uno aparece con sus 2 tools y cobra con su propio proveedor.
- [ ] Dado un agente con el MCP de un proveedor, cuando el usuario confirma qué paga y cuánto, entonces el AI genera el link llenando solo los inputs de negocio.
- [ ] Dado un link generado, cuando el AI consulta el estado con el `orderId`, entonces recibe el estado correcto del pedido.
- [ ] Dado un link generado, cuando el usuario paga, entonces el agente retoma la conversación con el resultado sin que el usuario escriba.
- [ ] Dado un MCP en producción con credenciales rechazadas por el PSP, cuando el AI genera un link, entonces la tool devuelve un error legible y el AI no inventa un link.
- [ ] Dado un `amount` por debajo del mínimo del PSP, cuando el AI genera un link, entonces la tool lo rechaza e indica el mínimo.
- [ ] Las tools **Pago WebView** y **Pago Confirmación Externa** ya no aparecen en el Marketplace ni en **Agregar tool**.

## Decisiones

- El MCP **Jelou Payments** se retira del Marketplace. Se reutiliza su conexión al core de pagos; el schema de las tools es nuevo.
- **Stripe** también genera el MCP de 2 tools al instalarse. Su MCP actual se mantiene para quien ya lo tiene, pero deja de ofrecerse en el Marketplace.
- **Pago WebView** y **Pago Confirmación Externa** se eliminan. El MCP del proveedor las cubre: para Deuna, **Generar enlace de pago** devuelve su código y la confirmación llega por **Obtener estado del pedido** y por el webhook (**10**).
- **Entorno.** El MCP usa el entorno en que está la integración, sin pedir `environment`.
- **Moneda, IVA, país y expiración** se configuran una vez por pasarela en **Pagos → Integraciones**, con defaults por país.
- **Probar con Jelou** usa las credenciales sandbox de Jelou para esa pasarela, siempre en Desarrollo.
- El agente retoma la conversación tras el pago con `resume-or-create`, disparado por el webhook del core.

## Preguntas abiertas

- **Fecha de corte.** Se fija cuando esté el inventario de bots que usan Pago WebView y Pago Confirmación Externa.

## Fuera de alcance

- La tool **Generar flujo de pago** (WhatsApp Flow) del MCP Jelou Payments.
- El diseño técnico de cómo se resuelven credenciales y datos sensibles por detrás. Se define más adelante.
- Qué pasa con los agentes cuando se desinstala una integración de pagos que usan como MCP.
